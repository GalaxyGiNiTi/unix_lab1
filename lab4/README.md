# Лабораторная работа №4: Горизонтально масштабируемый сервис

## Описание

Микросервисное приложение на **Go** для анализа текста, демонстрирующее горизонтальное масштабирование с использованием Docker и RabbitMQ.

**Функциональность:** Сервис подсчёта слов и символов в тексте с распределением нагрузки между несколькими worker'ами.

## Компоненты

| Компонент | Описание | Язык |
|-----------|----------|------|
| **Manager** | Управляющий контейнер, HTTP API | Go |
| **Worker** | Реплицируемый обработчик задач | Go |
| **RabbitMQ** | Брокер сообщений | - |

## Соответствие требованиям

| Требование | Реализация |
|------------|------------|
| ✅ Не менее двух типов контейнеров | Manager + Worker |
| ✅ Один брокер | RabbitMQ |
| ✅ Горизонтальное масштабирование | Worker масштабируется через `--scale` |
| ✅ Балансировка нагрузки | RabbitMQ round-robin + prefetch=1 |

## Запуск

### Базовый запуск (1 worker)

```bash
cd lab4
docker compose up --build
```

### Запуск с масштабированием (N workers)

```bash
# Запуск с 5 worker'ами
docker compose up --build --scale worker=5

# Или изменить количество на лету
docker compose up -d --scale worker=10
```

### Проверка работы

```bash
# Отправка запроса
curl -X POST http://localhost:8000/count \
  -H "Content-Type: application/json" \
  -d '{"text": "Hello world hello"}'

# Ответ:
{
  "word_count": 3,
  "char_count": 16,
  "words": {
    "hello": 2,
    "world": 1
  },
  "processed_by": "abc123def456"  # ID worker'а
}
```

### Health check

```bash
curl http://localhost:8000/health
# {"status": "ok", "service": "manager"}
```

## Веб-интерфейс RabbitMQ

После запуска доступен по адресу: **http://localhost:15672**

- Логин: `user`
- Пароль: `password`

Здесь можно наблюдать:
- Очередь `word_count_tasks`
- Количество подключённых consumers (workers)
- Статистику сообщений

## Демонстрация балансировки нагрузки

```bash
# Запускаем с 3 worker'ами
docker compose up --build --scale worker=3 -d

# Отправляем несколько запросов
for i in {1..10}; do
  curl -s -X POST http://localhost:8000/count \
    -H "Content-Type: application/json" \
    -d '{"text": "test message"}' | jq .processed_by
done
```

Вывод покажет разные ID worker'ов, что подтверждает распределение нагрузки.

## Технические детали

### RPC-паттерн (Request-Reply)

1. Manager создаёт временную очередь для ответа
2. Отправляет задачу с `correlation_id` и `reply_to`
3. Worker обрабатывает и отправляет ответ в указанную очередь
4. Manager получает ответ по `correlation_id`

### Балансировка нагрузки

RabbitMQ распределяет сообщения между worker'ами по принципу **round-robin**. Параметр `prefetch=1` гарантирует, что каждый worker получает следующую задачу только после завершения текущей.

### Graceful Shutdown

Worker'ы корректно обрабатывают сигналы `SIGINT` и `SIGTERM`, что позволяет безопасно масштабировать сервис.
