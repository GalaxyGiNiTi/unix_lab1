# Лабораторная работа №3: Жёсткие ссылки

## Описание задания

Консольное приложение на C++, которое:
1. Обходит указанный каталог и составляет список всех файлов
2. Вычисляет хэш для каждого файла
3. Для файлов с одинаковым хэшем оставляет один экземпляр, а остальные заменяет на жёсткие ссылки

## Что такое жёсткая ссылка?

**Жёсткая ссылка (hard link)** — это дополнительное имя для существующего файла в файловой системе. В отличие от символической ссылки, жёсткая ссылка указывает непосредственно на тот же inode (структура данных, описывающая файл на диске).

Особенности жёстких ссылок:
- Все жёсткие ссылки на файл равноправны — нет "оригинала" и "копии"
- Файл удаляется только когда удалены все жёсткие ссылки на него
- Жёсткие ссылки можно создавать только в пределах одной файловой системы
- Нельзя создавать жёсткие ссылки на каталоги (кроме `.` и `..`)

## Используемые технологии

| Компонент | Описание |
|-----------|----------|
| `std::filesystem` | Стандартная библиотека C++17 для работы с файловой системой |
| `recursive_directory_iterator` | Рекурсивный обход каталога |
| `stat()` | POSIX-функция для получения информации о файле (устройство, inode) |
| FNV-1a | Быстрый некриптографический хэш-алгоритм |

## Алгоритм хэширования FNV-1a

Программа использует **FNV-1a (Fowler–Noll–Vo)** — быстрый некриптографический хэш:

```cpp
hash = FNV_OFFSET_BASIS  // 14695981039346656037
for each byte:
    hash = hash XOR byte
    hash = hash * FNV_PRIME  // 1099511628211
```

Преимущества:
- Очень быстрый
- Хорошее распределение значений
- Простая реализация

## Пример работы

```bash
$ mkdir test && echo "hello" > test/a.txt && echo "hello" > test/b.txt && echo "world" > test/c.txt

$ ./lab3 test
Обход каталога: test
[UNIQUE] test/a.txt
[UNIQUE] test/c.txt
[DUPLICATE] test/b.txt -> test/a.txt
Готово.

$ ls -li test/
42452599 -rw-r--r--  2 user  staff  6 Dec  1 16:15 a.txt
42452599 -rw-r--r--  2 user  staff  6 Dec  1 16:15 b.txt  # тот же inode!
42452600 -rw-r--r--  1 user  staff  6 Dec  1 16:15 c.txt
```

Обратите внимание:
- `a.txt` и `b.txt` имеют **одинаковый inode** (42452599)
- Счётчик ссылок для них равен **2**
- Это означает, что файлы физически хранятся один раз, но имеют два имени

## Вывод программы

| Метка | Значение |
|-------|----------|
| `[UNIQUE]` | Файл с уникальным содержимым, сохранён как эталон |
| `[DUPLICATE]` | Найден дубликат, заменён на жёсткую ссылку |
| `[ALREADY LINKED]` | Файлы уже являются жёсткими ссылками друг на друга |

## Защита от ошибок

1. **Разные файловые системы** — программа проверяет `st_dev` и не пытается создать ссылку между разными устройствами

2. **Уже существующие ссылки** — проверка `st_ino` предотвращает повторную обработку файлов, которые уже связаны

3. **Коллизии хэша** — дополнительная проверка размера файла защищает от (маловероятных) коллизий хэш-функции

4. **Ошибки доступа** — все операции обёрнуты в проверки `error_code`

## Структура кода

```

└── main()
    ├── Парсинг аргументов
    ├── Проверка существования каталога

```
