# Лабораторная работа 2: TCP-сервер с безопасной обработкой сигналов

## Описание

Программа реализует TCP-сервер, который демонстрирует безопасную работу с сигналами в многопоточной среде без использования race conditions. Сервер использует `pselect()` для атомарной обработки событий на сокетах и сигналов.

## Функциональность

- **Прием TCP-соединений** на указанном порту (по умолчанию 5555)
- **Управление соединениями**: принимается только одно активное соединение, все последующие закрываются сразу после подключения
- **Обработка данных**: при получении данных выводится количество принятых байтов
- **Обработка сигналов**: при получении SIGHUP выводится сообщение на терминал
- **Безопасность**: использование `pselect()` с правильной блокировкой сигналов исключает race conditions

## Компиляция

```bash
g++ -o server main.cpp -Wall -Wextra
```

Или с дополнительными флагами оптимизации:

```bash
g++ -o server main.cpp -Wall -Wextra -O2 -std=c++11
```

## Запуск

### Запуск на порту по умолчанию (5555):
```bash
./server
```

### Запуск на произвольном порту:
```bash
./server 8080
```

После запуска программа выведет сообщение с PID процесса:
```
Listening on port 5555. PID=12345 (send: kill -HUP 12345)
```

## Тестирование

### 1. Отправка сигнала SIGHUP

В другом терминале отправьте сигнал процессу:
```bash
kill -HUP <PID>
```

Где `<PID>` — это идентификатор процесса, выведенный при запуске.

Ожидаемый вывод:
```
[signal] SIGHUP received
```

### 2. Подключение TCP-клиента

Используйте `telnet`, `nc` или другой TCP-клиент:

```bash
telnet localhost 5555
```

Или:
```bash
nc localhost 5555
```

Ожидаемый вывод сервера:
```
[tcp] new connection fd=4 from 127.0.0.1:54321
[tcp] keeping fd=4
```

### 3. Отправка данных

После подключения введите любой текст в клиенте и нажмите Enter.

Ожидаемый вывод сервера:
```
[tcp] received 13 bytes on fd=4
```

### 4. Проверка "одно соединение"

Подключите второго клиента, пока первый еще активен:

```bash
nc localhost 5555
```

Ожидаемый вывод сервера:
```
[tcp] new connection fd=5 from 127.0.0.1:54322
[tcp] closing extra fd=5
```

Второе соединение будет немедленно закрыто.

### 5. Закрытие соединения

Закройте клиент (Ctrl+C или Ctrl+D).

Ожидаемый вывод сервера:
```
[tcp] peer closed fd=4
```

## Технические детали

### Безопасная обработка сигналов

Программа использует следующую схему для исключения race conditions:

1. **Блокировка SIGHUP** с помощью `sigprocmask(SIG_BLOCK)` до установки обработчика и входа в главный цикл
2. **Обработчик сигнала** устанавливает атомарный флаг `g_hup` (тип `volatile sig_atomic_t`)
3. **pselect()** атомарно разблокирует SIGHUP и ожидает события, после возврата снова блокирует сигнал
4. **Проверка флага** в начале каждой итерации цикла

Это гарантирует, что:
- Сигнал не будет потерян между проверкой флага и вызовом `pselect()`
- Сигнал корректно прервет ожидание в `pselect()`
- Нет необходимости в дополнительной синхронизации

### Неблокирующие операции

- Все сокеты переводятся в неблокирующий режим (`O_NONBLOCK`)
- `accept()` вызывается в цикле до получения `EAGAIN`/`EWOULDBLOCK`
- Чтение данных обрабатывает `EAGAIN`/`EWOULDBLOCK`/`EINTR` корректно

### Флаг FD_CLOEXEC

Все файловые дескрипторы создаются с флагом `FD_CLOEXEC`, чтобы они не наследовались дочерними процессами при вызове `exec()`.

### Вывод сообщений

Используется функция `xwritef()`, которая обходит буферизацию stdio и напрямую использует `write()` для безопасного вывода в асинхронном контексте.

## Требования

- POSIX-совместимая система (Linux, macOS, BSD)
- Компилятор C++ с поддержкой C++11
- Стандартные POSIX библиотеки

## Структура кода

- `on_hup()` — обработчик сигнала SIGHUP
- `set_nonblock()` — установка неблокирующего режима для дескриптора
- `set_cloexec()` — установка флага FD_CLOEXEC
- `xwritef()` — безопасный вывод форматированных сообщений
- `make_listen_socket()` — создание слушающего TCP-сокета
- `main()` — главный цикл обработки событий

## Примечания

- Программа работает в бесконечном цикле, для завершения используйте Ctrl+C
- При работе на Windows требуется WSL или аналогичная POSIX-среда
- Порт должен быть свободен (не занят другими приложениями)
